# TelegramTableside

> Pretty markdown rendering for Telegram bots, including markdown pipe tables as inline PNGs.

`markdownToTelegramHtml` for safe Markdown -> HTML, plus a `sendPhoto`-based path that makes `| pipe | tables |` actually render as inline visual tables in chat. Pure-JS, ~3 MB install, no native build step.

## The problem

Telegram's Bot API supports two text-formatting modes for outbound messages:

**`MarkdownV2`** — strict markdown. Looks easy until you realize you have to backslash-escape every `_ * [ ] ( ) ~ \` > # + - = | { } . !` that isn't part of a formatting marker. One missed escape returns `400 Bad Request: can't parse entities` and the message is silently dropped. For a bot whose text content is generated by an LLM or templated from user data, MarkdownV2's escape regime is too brittle in practice. Mistakes are easy and consequences are total (message lost).

**`HTML`** — Telegram's HTML parse_mode subset. Far more lenient — only `<`, `>`, `&` need escaping, and Telegram silently strips or rejects unknown tags rather than dropping the whole message. *But*: the supported tag set is `<b> <i> <u> <s> <code> <pre> <a> <blockquote> <tg-spoiler>`. No `<table>`, no `<ul>`, no `<img>`. Tables are off the menu.

For everything else, Telegram supports `sendDocument` (PDFs etc.) — but those render in chat as a thumbnail tile that the user has to *tap* to open in the document viewer. That fails any "inline rendering" requirement.

The only message type that renders true inline rich content (visible in the chat without a tap) is `sendPhoto` / `sendAnimation`. So if you want pretty tables to appear inline, you need to render them to images.

This library does that — and packages it alongside a forgiving Markdown -> HTML converter so a bot's outbound markdown becomes Telegram-ready without the caller having to think about parse modes, escape rules, or attachment types.

## What this library does

Given a string of LLM- or templated- generated markdown:

```text
## Tuesday session bias

**Macros are heading into Tuesday with mixed signals.** Watch
the cash open carefully.

| Symbol | Last  | Day % | RVOL |
|--------|-------|-------|------|
| ES=F   | 7511  | +0.6% | 1.2x |
| NQ=F   | 29651 | +0.7% | 1.4x |
| YM=F   | 50690 | +0.6% | 0.9x |
| RTY=F  | 2863  | +0.6% | 0.8x |

Plan: trade the breakout retest, not the breakout itself.
```

`prettifyForTelegram(markdown)` returns an ordered stream of send-ready segments:

```ts
[
  { kind: 'html', html: '<b>Tuesday session bias</b>\n\n<b>Macros are heading into Tuesday with mixed signals.</b> Watch\nthe cash open carefully.' },
  { kind: 'png',  png: <Buffer>, name: 'table-1.png' },
  { kind: 'html', html: 'Plan: trade the breakout retest, not the breakout itself.' },
]
```

The caller iterates and dispatches each segment to Telegram in order — `html` via `sendMessage(parse_mode: 'HTML')`, `png` via `sendPhoto(InputFile)`. The user sees them appear in sequence in the chat, which reads as a single reply with an inline table.

## Install

```bash
bun add telegramtableside
# or
npm install telegramtableside
# or
yarn add telegramtableside
```

Runtime dependency: [`@resvg/resvg-js`](https://www.npmjs.com/package/@resvg/resvg-js) (pure WASM SVG renderer; no native build step, no Chromium download).

This library is provider-agnostic — it doesn't import a Telegram client. You wire it to whatever Bot API client you're using ([`grammy`](https://grammy.dev/), [`node-telegram-bot-api`](https://github.com/yagop/node-telegram-bot-api), [`Telegraf`](https://telegraf.js.org/), or raw `fetch` against `api.telegram.org`).

## Quick start

```ts
import { prettifyForTelegram } from 'telegramtableside'
import { Bot, InputFile } from 'grammy'

const bot = new Bot(process.env.TELEGRAM_TOKEN!)

bot.on('message:text', async ctx => {
  const markdown = await yourBotLogic(ctx.message.text)
  const segments = await prettifyForTelegram(markdown)

  for (const seg of segments) {
    if (seg.kind === 'html') {
      await ctx.api.sendMessage(ctx.chat.id, seg.html, { parse_mode: 'HTML' })
    } else {
      await ctx.api.sendPhoto(ctx.chat.id, new InputFile(seg.png, seg.name))
    }
  }
})

bot.start()
```

That's the whole integration. The library has no state, no side effects, no network calls, and no init step.

## API

### `prettifyForTelegram(input: string): Promise<RenderedSegment[]>`

The convenience wrapper. Returns an ordered list of `{ kind: 'html', html: string }` and `{ kind: 'png', png: Buffer, name: string }` segments. Dispatch them in order via the Telegram client of your choice.

### `markdownToTelegramHtml(input: string): string`

Pure function. Takes markdown, returns a string safe to pass to Telegram's `sendMessage` with `parse_mode: 'HTML'`. Code/`<pre>` regions are isolated before further substitution, so backticks and asterisks inside fences don't get mangled.

### `splitOnTables(input: string): SourceSegment[]`

Pure function. Detects markdown pipe-table regions and returns an ordered list of `{ kind: 'text', content: string }` and `{ kind: 'table', data: { rows: string[][] } }` segments. Use directly if you want to customize the rendering of text or table segments before dispatching.

### `tableToPng(table: TableData, opts?: Partial<TableStyleOpts>): Buffer`

Render a parsed table to a PNG buffer. The `opts` param lets you override font size, padding, colors, and border style. Defaults are tuned for readability on phone screens at typical Telegram zoom.

### `tableToSvg(table: TableData, opts?): string` / `tableSvgToPng(svg: string, scale?): Buffer`

The two halves of `tableToPng`, exposed separately for callers who want the intermediate SVG or want to combine with other SVG sources before rasterizing.

## How table rendering works

```
markdown input
     │
     │  splitOnTables() regex passes the text exactly once,
     │  detects /^\|.+\|\s*\n\|[\s\-:|]+\|\s*\n(?:^\|.+\|\s*\n?)+/gm
     ▼
[text seg, table seg, text seg, table seg, ...]
     │
     │  for each kind:
     │
     ├─ text  ─→ markdownToTelegramHtml() ─→ Telegram HTML string
     │            (escape <>& → format ** ` ``` [] ~~ ## → tags)
     │
     └─ table ─→ tableToSvg()              ─→ tableSvgToPng()      ─→ PNG buffer
                  (column-width measure +     (resvg-js @ 3x scale,
                   monospace cell text +       system font load,
                   bordered grid)              "Cascadia Code" preferred)
     │
     ▼
[{ kind:'html', html }, { kind:'png', png, name }, ...]
     │
     ▼
caller dispatches each in order
```

The split is one pass with no backtracking. Table SVGs are tightly cropped to content (no outer margins) so Telegram's auto-scaling shows the table edge-to-edge in the chat bubble.

The monospace font fallback chain is `"Cascadia Code","Consolas","Segoe UI Mono","JetBrains Mono",monospace`. `Cascadia Code` ships with Windows Terminal and gives the cleanest look on Windows servers; `Consolas` is a near-universal fallback on Windows; `Segoe UI Mono` and `JetBrains Mono` cover most Linux/macOS systems. `monospace` is the final generic fallback. `resvg-js` is told to `loadSystemFonts: true`.

## Markdown subset supported

| Source                  | Renders as                            | Notes |
|-------------------------|---------------------------------------|-------|
| `**bold**`              | `<b>bold</b>`                         | |
| `` `inline code` ``     | `<code>inline code</code>`            | Region extracted before other substitution |
| ` ```fenced``` `        | `<pre>fenced</pre>`                   | Multi-line OK; backticks/asterisks inside stay literal |
| `[text](url)`           | `<a href="url">text</a>`              | URL not validated; escape rules handled |
| `~~strike~~`            | `<s>strike</s>`                       | |
| `## Header` (any level) | `<b>Header</b>`                       | Telegram HTML has no `<h*>` |
| `\| a \| b \|` table    | inline PNG via `sendPhoto`            | Requires `\|---\|---\|` separator under header row |
| `<`, `>`, `&`           | `&lt;`, `&gt;`, `&amp;`               | Done before any other substitution |

Italic (`*foo*` or `_foo_`) is not yet handled — see [Roadmap](#roadmap).

## Why PNG and not PDF, MarkdownV2, or a custom client

| Approach | Inline render? | Effort | Maintenance | Verdict |
|----------|----------------|--------|-------------|---------|
| **PNG via sendPhoto** (this library) | yes, image visible without tap | low | none | the right tradeoff |
| MarkdownV2 with escape | only if everything escaped right | medium | one missed escape = silent 400 | brittle |
| PDF via sendDocument | no — thumbnail tile, tap to open | low | none | fails inline requirement |
| HTML with `<table>` | n/a — Telegram strips the tag | n/a | n/a | not possible |
| Fork tdesktop / mobile clients | yes (per platform) | very high (~1.5M LOC each) | upstream rebase forever | wildly disproportionate |
| Custom MTProto client | yes (your client only) | very high | every Telegram feature is yours now | only if rendering tables is your whole product |

PNG is the only path that gets inline rendering on every official client (mobile, desktop, web) without forking anything. The tradeoffs are real — no text selection inside the rendered table, links inside the table become non-clickable — but those costs scoped to the table region only.

## Performance and footprint

- **Install:** ~3 MB on disk (just `@resvg/resvg-js` and its WASM blob).
- **Cold render:** first call into `@resvg/resvg-js` initializes the WASM module. Subsequent calls reuse it.
- **Per-table:** typical 4×4 table renders to a ~40-60 KB PNG in well under 100 ms on a modern machine.
- **Memory:** no persistent state. Each call constructs an SVG string, hands it to resvg, gets a Buffer back, returns. GC-friendly.
- **No network calls:** entirely local; doesn't fetch fonts or resources at render time.

## Known limitations

- **Column alignment markers ignored.** `:---`, `---:`, `:---:` in the separator row are parsed but not yet rendered — all cells left-align.
- **Italic not supported.** Single-`*` and single-`_` runs pass through as literal characters. Adding italic safely (without colliding with snake_case in code, or with bare asterisks in technical content) needs careful regex design.
- **No nested table support.** Markdown doesn't have nested tables, but if you somehow construct one, behavior is undefined.
- **Long messages may break at HTML boundaries.** Telegram's per-message limit is 4096 characters. Long text segments are chunked before HTML conversion (the chunker is whitespace-aware but not HTML-aware). A chunk boundary that cuts a `**...**` pair produces an unclosed `<b>` tag — Telegram rejects with 400. In practice, default chunk size accommodates most replies in one chunk and the issue doesn't appear. HTML-aware chunking is on the roadmap.
- **Wide tables get downsized by Telegram.** Telegram caps photo dimensions; very wide tables (10+ columns) get auto-scaled down and text becomes small. Render time tables to fit the typical phone-bubble aspect ratio.

## Failure modes and how they manifest

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Table renders as raw pipe text instead of image | Regex didn't match — usually a missing `\|---\|---\|` separator row, or uneven column counts | Make sure the source has a separator row with the right number of pipe-delimited dashes |
| 400 from `sendMessage` on a text segment | `**` or `` ` `` pair split across a chunk boundary | Reduce input length, or wait for HTML-aware chunking |
| Table font looks "wrong" / ugly | System doesn't have any of the preferred monospace fonts; resvg fell back to its built-in font | Install `Cascadia Code` or `JetBrains Mono`, or pass a custom font path via your fork |
| Photo arrives but table content is cut off | Table is wider than Telegram's downscale threshold | Reduce columns; future versions may auto-split very wide tables |
| Generates an empty PNG / fails silently | The detected "table" had fewer than 3 lines after separator-strip | Confirm the source had a header row, separator, and at least one data row |

## Roadmap

- Column alignment (`:---`, `---:`, `:---:`) honored in render
- Italic (`*foo*` / `_foo_`) with word-boundary safety
- HTML-aware chunking (split at safe boundaries, never mid-tag)
- Optional auto-split for ultra-wide tables (>10 columns)
- Configurable theme presets (light/dark, monospace/proportional)
- Embedded fallback font bundled with the package (so renders don't depend on system fonts being installed)
- Optional batch-render for media-group (multiple tables in one Telegram album)

## Contributing

Issues and pull requests welcome. The codebase is intentionally small (~500 lines across three files) — `src/markdown.ts`, `src/table.ts`, `src/index.ts`. The whole library is pure functions with no I/O outside of resvg, which makes adding tests straightforward.

Style: TypeScript, no semicolons (matching Bun's defaults), 2-space indent. Prefer regex + small string transforms over a full AST for the markdown subset — the parsing target is small enough that the readability win of regex-per-feature beats the rigor of a parser.
